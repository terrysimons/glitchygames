Code Complexity Metrics#

How the most complex modules in src/glitchygames/ changed over the project's git history, measured by wily. The modules are the 15 with the highest total cyclomatic complexity (the sum over their functions and methods) at the published commit. Each graph has one line per module (click a module in the legend to hide or show it), with a point at each commit that changed the module's value. wily follows files by path; the engine moved from the repository root into src/glitchygames/ (2026-10-25), so each module's measurements under its former path are joined to its current one (MOVED_PATH_PREFIXES in scripts/generate_complexity_graphs.py), and its line runs through its whole history.

The graphs are generated, not kept in git: nox -s docs-deploy generates them before it builds the published site. To see them in a local build (mkdocs serve), generate them first with uv run python scripts/generate_complexity_graphs.py (or nox -s code-complexity -- --graphs), which measures the committed history (HEAD) in a temporary worktree and writes them to docs/quality/graphs/; until then this page has only this text.

Generated at commit e81c311 (2026-10-31) from all 249 commits. The modules, highest total cyclomatic complexity first: src/glitchygames/scenes/scene.py, src/glitchygames/engine/game_engine.py, src/glitchygames/sprites/animated.py, src/glitchygames/replay/driver.py, src/glitchygames/ui/text_widgets.py, src/glitchygames/replay/tools/measure.py, src/glitchygames/recording.py, src/glitchygames/recording_metrics.py, src/glitchygames/input/devices.py, src/glitchygames/tracing.py, src/glitchygames/replay/tools/performance_pages.py, src/glitchygames/replay/playback.py, src/glitchygames/sprites/bitmappy_sprite.py, src/glitchygames/sprites/pixel_utils.py, src/glitchygames/ai/sprite_generator.py.
