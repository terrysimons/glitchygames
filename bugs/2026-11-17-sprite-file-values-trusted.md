# Sprite File Values Were Trusted As Written

- **Description**: The sprite loaders copied a file's values into the sprite without checking their type or range. A `frame_interval` of text (`frame_interval = "fast"`) loaded without a word, and the game crashed on its first frame, in `AnimatedSprite.update` (`'>=' not supported between instances of 'float' and 'str'`), far from the file that caused it. The same class: `loop = "false"` (text) counted as true; text in a color channel or a hitbox number failed at load with an unclear error (pygame's "invalid color", or a `TypeError` building a `pygame.Rect`); a misspelled key was silently ignored. The audit that followed found one tracked file broken that way: `scripts/animated.toml` wrote its frames as `[[animation.frames]]`, a key the loader does not read, so it loaded with no animation at all and `scripts/animation_demo.py` showed nothing
- **Status**: Fixed (2026-11-17, branch `feat/sprite-generation-in-the-ai-service`)
- **Priority**: Medium (a sprite file a person writes by hand, or an AI writes, can crash a game mid-play)
- **Root Cause**: no check between parsing a sprite file (`tomllib`) and building the sprite from it; each value was read with `dict.get` and used as it came
- **Test gap**: the loaders' tests covered malformed pixel rows (`normalize_pixel_rows`) but never a value of the wrong type; and no test checked sprite files outside the packages' own sprite folders, so `scripts/animated.toml` had none
- **Solution**: `src/glitchygames/sprites/sprite_file_schema.py`, a pygame-free pydantic schema (strict: text is never a number, a boolean never a number), checked by both loaders (`AnimatedSprite._load_toml`, `BitmappySprite`'s two load paths) right after parsing: `frame_interval` a positive number of seconds; color channels and alpha 0 to 255; hitbox sizes and frame indexes whole numbers from 0, offsets whole numbers; `loop` a boolean; `tags` a list of text; unknown keys inside the sections the engine reads refused (a game's own top-level table, Drawing Fire's `swatches`, is kept). A bad file fails at load naming the file and the field (`fast.toml: animation.0.frame_interval: Input should be a valid number`). `scripts/animated.toml`'s two `[[animation.frames]]` are `[[animation.frame]]` now: it loads its `idle` animation's two frames
- **Tests**: `tests/sprites/test_sprite_file_schema.py` (15 named bad values, misspelled keys, a game's own table kept, the reported bug at load for both loaders, and the invariant over the class: every field a file holds refuses a value of the wrong type); `glitchygames.testing.sprite_files.check_values_match_the_schema` at the four sprite-file sites; `tests/test_repository_sprite_files.py` (every tracked sprite file, wherever it lives, passes the schema; it fails on the old `scripts/animated.toml`)
