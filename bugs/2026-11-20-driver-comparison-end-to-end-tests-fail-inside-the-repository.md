# Inner Pytest Runs Fail When Their Temporary Folder Is Inside the Repository

- **Description**: `tests/test_driver_comparison.py::TestEndToEnd::test_dummy_only_runs_one_driver`, `::test_a_frame_difference_fails_the_run_with_images` and `::test_a_failure_in_the_second_run_fails_this_run` fail whenever pytest's temporary folder is inside the repository, and pass when it is outside. Found 2026-11-20 by the process-stop reproducer (`scripts/reproduce_process_stop_under_load.py`), which first put each round's `--basetemp` under the repository's `build/`: they failed in 20 of 20 rounds there (the third in 14). Isolated (2026-11-20):
  - inside the repository: `--basetemp build/…` (relative), `--basetemp /…/<repository>/build/…` (absolute), with or without the probe on `PYTHONPATH`, and `PYTEST_DEBUG_TEMPROOT=<repository>/build/…` (no `--basetemp`): fail;
  - outside it: pytest's default temporary folder, `--basetemp` in the scratch folder, `PYTEST_DEBUG_TEMPROOT` in the scratch folder: pass.
  Failures seen: `ExitCode.TESTS_FAILED` where `OK` was expected; `ValueError: Pytest terminal summary report not found`; `nomatch: '*driver comparison: dummy vs dummy-2*'`.
- **Wider than first seen** (2026-11-21): every file whose tests run pytest on a project of their own was run with `--basetemp` inside the repository and outside it. Inside, 25 tests in 7 files failed: `tests/replay/test_replay_plugin.py` (10), `tests/test_frame_fingerprints.py` (5), `tests/test_circleci_test_split.py` (5), `tests/test_memory_guard.py` (2), `tests/test_driver_comparison.py` (2 of the 3 above; the third failed in 14 of 20 rounds), `tests/test_collection_logger_levels.py` (1). Outside, all 277 passed.
- **Status**: Fixed (2026-11-21, `fix/pytester-projects-own-their-config`)
- **Priority**: Low (test only; the default temporary folder is outside the repository, but a run that places it inside, a triage tool's `--basetemp` or a container with `TMPDIR` in the checkout, couldn't run these tests)
- **Root Cause** (measured, 2026-11-21): a pytester project held no configuration file, so pytest looked for one in the folders above it. Inside the repository, the inner run's header read `rootdir: <repository>`, `configfile: pyproject.toml`, `created: 16/16 workers`: it took the repository's addopts (xdist, `--cov` with `fail-under = 100`) and its conftest. Its own tests passed, then coverage failed the run (27.54% of 100%). Outside, its rootdir was its own folder.
- **Test gap**: the tests assumed their `tmp_path` lies outside any project; nothing checked that assumption, and no run placed the temporary folder inside the repository.
- **Fix**: the harness's pytester hook (`tests/harness.py`, `inner_runs_keep_their_order`) gives every pytester project a `tox.ini` holding `[pytest]` (`give_project_its_own_config`), so pytest's search, its rootdir and its conftest search stop at the project. `tox.ini` is the lowest-precedence file pytest reads in a folder, so a project's own `pytest.ini`, or a `pyproject.toml` with `[tool.pytest.ini_options]`, still wins (pytest 9 then notes the ignored `tox.ini` in the header only). One shared code path, not seven file edits: it covers every pytester test, present and future. Tests in `tests/test_inner_runs.py`: a project inside another project stops the search at itself (red before the fix), every pytester project reads its own file (red before), and a project's own `pytest.ini` and `pyproject.toml` still win. With the fix, the files above pass inside the repository too (282 passed, 2 skipped), in 8 s instead of 104 s.
- **Not covered by the fix**: a test that starts pytest itself, without pytester, must write its project's configuration file as `tests/test_driver_comparison.py`'s stopping tests do (`pytest.ini` beside the stand-in test).
- **Workaround** (before the fix): `scripts/reproduce_process_stop_under_load.py` puts each round's `--basetemp` in a fresh folder outside the repository and moves it into the round's folder only when the round fails.
