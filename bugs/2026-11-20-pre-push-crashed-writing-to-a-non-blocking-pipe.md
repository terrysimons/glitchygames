# The Pre-Push Hook Crashed Writing Its Output to a Non-Blocking Pipe

- **Description**: A `git push 2>&1 | tail` died in the pre-push hook with `BlockingIOError: [Errno 35]` (macOS EAGAIN) while pre-commit printed the output of `test-random`, after the checks had passed (found 2026-11-20 by the overnight session's perf push; triage in `.superpowers/overnight-2026-11-20/triage.md`, section 2). A push to a terminal or into a file did not fail.
- **Status**: Fixed (2026-11-20, branch `fix/pre-push-robustness`)
- **Priority**: Medium (a lost push after a long gate; a rerun succeeds, so it looks like a flake)
- **Root Cause**: OpenSSH's `ssh`, git's transport for `git@github.com`, sets `O_NONBLOCK` on its inherited stdout and stderr when they are not terminals. git runs the pre-push hook with those same open file descriptions, and the flag belongs to the open file description, so the hook's fd 1 and fd 2 are non-blocking. pre-commit prints each hook's captured output in one burst when the hook ends, and `test-random`'s is large; into a pipe whose reader lags (`tail`) the burst overflows the pipe buffer and `write` returns EAGAIN. Measured with a scratch hook and `git push --dry-run origin ...` (nothing pushed): through `| cat` stdout and stderr were both non-blocking over ssh; into a file also (files never fail with EAGAIN); to a local bare remote (no ssh) through a pipe, blocking; a terminal is exempt. Our own chain (`uv run`, pytest, xdist, nox) leaves both blocking. A non-blocking pipe with a slow reader and one burst raised exactly `BlockingIOError(35)` from `sys.stdout.write`.
- **Test gap**: Nothing ran a hook with its output on a slow pipe, and nothing checked the hook's descriptors for `O_NONBLOCK`; the hook environment of a real push (ssh in the middle) was never part of any test.
- **Solution**: The installed pre-push shim clears `O_NONBLOCK` on fd 1 and fd 2 before it starts pre-commit (`os.set_blocking(1, True); os.set_blocking(2, True)`, run by `$INSTALL_PYTHON` or `python3`; harmless on a terminal or a file; the flag is on the shared open file description, so clearing it persists and ssh does not set it again). The shim is generated by `pre-commit install`, so `scripts/patch_pre_push_hook.py` inserts the step after it, idempotently, finding the hooks folder as git does (`git rev-parse --git-path hooks`: worktrees share their repository's hooks, `core.hooksPath` is honoured). `.envrc` runs it on every entry, after the install-when-missing branch, so an existing clone gets it and a later `pre-commit install` is patched again. The rule is written in the script's docstring. A shim the script does not recognise (pre-commit changed its template) exits `UNUSABLE_INPUT` and `.envrc` says so.
- **The class, and its invariant**: a process whose standard output or error a parent may have left non-blocking writes a burst larger than the pipe buffer without handling EAGAIN. The invariant: a hook (a process git starts with ssh's descriptors) clears `O_NONBLOCK` before it writes. `tests/test_patch_pre_push_hook.py` holds it for the installed pre-push hook with the pipe's write end non-blocking and a slow reader, for stdout and for stderr: the unpatched hook's burst raises `BlockingIOError`, the patched one's arrives whole. `test_envrc_patches_the_hook_whether_or_not_it_was_just_installed` keeps `.envrc` applying it.
- **Sweep** (processes git or ssh start that write large output): covered: the pre-push hook, the only hook that runs the long gate. Uncovered: the pre-commit-stage shim (its output is small: the replay-metrics hook's lines) is not patched; the shim's own pre-commit start is covered, but a hook's child that sets a descriptor non-blocking again itself is not seen; a push through a non-ssh transport (https) is untested because its transport was not measured to set the flag.
- **Tests**:
  - `tests/test_patch_pre_push_hook.py::TestTheBlockingPipeFailure`: `test_without_the_step_the_burst_raises_blocking_io_error` (the reproduction; the real shim from `pre-commit install`, a 512 KiB burst, a non-blocking pipe with a 4 KiB-per-millisecond reader: the burst fails with `BlockingIOError`) and `test_with_the_step_the_burst_arrives_whole` (patched: exit 0, every byte received), each for stdout and stderr. The second fails on the unpatched hook (the first test shows the failure it would hit).
  - `TestPatching`: the step goes in once, before pre-commit starts, and nothing else of the shim changes; idempotent; the hook stays executable; a re-installed shim is patched again; a missing or unknown hook is reported and left alone.
  - `TestWhereTheHookIs`: repository, worktree, `core.hooksPath`, not a repository.
  - The patched hook still runs pre-commit with its arguments and passes its exit code; with no interpreter on `PATH` the step is skipped and the shim's tail runs.
