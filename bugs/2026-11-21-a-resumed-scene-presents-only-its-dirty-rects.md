# A Resumed or Switched-To Scene Presents Only Its Dirty Rects

- **Description**: when a scene becomes active (a switch, a resume from the pause screen, a playback scope's live scene coming back), `SceneManager` blits the scene's whole background onto the screen surface (`_configure_active_scene` and `_resume_live_scene` call `_redraw_scene_background`), but the next present is a dirty-rect update (`_update_display`: `pygame.display.update(scene.rects)`). Everything outside the sprites' rects changed on the surface and was never sent to the window, so a driver that honors rect updates keeps the previous scene's picture there (the pause screen around the sprites).
- **Status**: Open, latent (not visible in any window the engine opens; fix planned on `fix/static-sprites-full-screen-update` so the present path stays correct without relying on the window)
- **Priority**: Low (no window the engine opens can show it: see below)
- **Measured** (2026-11-21, main `94360cd9`, every golden and bundled demo replayed headless with `_update_display` instrumented to compare the surface before and after each present outside the rects sent): two frames, both resuming from `PauseScene`: Paddleslap's golden, the `Game` scene's frame 452 (5 rects), and Zombies' golden, `TitleScene`'s frame 247 (5 rects). Every other present sent every changed pixel.
- **Reproduces on a real window**: no, because every window the engine opens is SCALED. Two look tests on the cocoa driver (the owner, 2026-11-21, pygame-ce 2.5.8, SDL 2.32.10): a red window, then the surface filled blue with only an 80x80 rect at the top-left sent through `pygame.display.update(rects)`. Without SCALED (a plain 320x240 window) the window showed a blue band the full width and 80 rows tall over red: cocoa presents whole rows spanning the rects. With the engine's own flags (`DOUBLEBUF | SCALED | RESIZABLE`, `GameEngine` in `engine/game_engine.py`, windowed or fullscreen) the whole window turned blue: a SCALED display presents through SDL's renderer, which shows the whole surface on every update. Headless runs open no window (`mode_flags = 0`, the dummy driver). So the owner's live pause and resume of Zombies' title came back clean, as it must, though a shadow window applying only what each present sends (exact rects, or cocoa's rows) holds rows 216-253 stale for the 14 title frames after the resume in Zombies' golden. Not checked: the browser's canvas (the same engine code asks for SCALED there too) and other desktop drivers.
- **Root cause**: the full background blit on activation has no matching full present. `_display_is_stale`, which makes the next present flip the whole surface, is set for the other cases where the window falls behind the surface (shifted or overlaid frames, unpresented frames, a playback scope's switch), but not for a switch or resume.
- **Test gap**: the driver comparison (docs/quality/driver_comparison.md) and the goldens compare the screen surface, never what was presented to the window, so a present that leaves the window behind the surface is invisible to every check. Today's `Scene.update` also marks every sprite dirty every frame (`scenes/scene.py`, the never-cleared `Scene.dirty`), so the rects cover every sprite and the stale area is only the background between them; clearing that flag would widen it.
- **Planned solution**: a switch or resume sets `_display_is_stale`, so the next present flips the whole surface; a shadow-window invariant (apply only what each present sends, compare with the surface) over every golden, every demo and targeted cases, failing first on this bug.
