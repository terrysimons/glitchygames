# Bitmappy's Arcade Tile Diverged at Frame 0: It Read the Host's Window as Its Screen

- **Description**: Bitmappy's bundled demo (`demos/drawing.jsonl.gz`), replayed as an Arcade tile inside a 1280x720 outer window, diverged at frame 0: `FilmStripSprite#0` rect expected `[350, 24, 450, 124]`, got `[350, 24, 930, 124]`. The other tiles matched their solo replays. Found 2026-11-12 by Arcade sub-plan 3 and held by a strict xfail in `tests/test_every_recording_replays_inside_an_inner_game.py`. Standalone, the same demo replays all 900 frames, both as recorded and with `-r 1280x720` (the recording fixes 800x480), so the bug showed only inside another game.
- **Status**: Fixed (2026-11-20, branch `fix/bitmappy-reads-its-own-screen`)
- **Priority**: Medium (blocked Bitmappy's tile on the Arcade screen, Arcade sub-plan 6)
- **Root Cause**: Bitmappy sized its film strip, its canvas and its controller indicators from `pygame.display.get_surface()` (`film_strip_coordinator.py:348`, `animated_canvas.py:1631`, `controllers/visual_indicators.py:326`). That is SDL's one window per process: inside a tile it is the host's 1280x720 window, not the tile's 800x480 render target, so the strip ran to `1280 - 350 = 930`. Shown by Arcade sub-plan 5's planning agent: answering that call with the render target in a scratch run made all 900 frames match.
- **Test gap**: Bitmappy's tests run in the default context only, where the display is the screen, and nothing kept a game, demo or app from calling pygame for the whole process instead of through the engine (`glitchygames.render_target.display_surface()`, which CLAUDE.md already requires of engine code).
- **Solution**: The owner chose to change Bitmappy, as an exception to "wrapping a game needs no changes to the game" ("I think this particular situation warrants fixing bitmappy not to use pygame calls directly", 2026-11-20). Replacing pygame functions per context (option A in `plans/2026-11-20-arcade-5-playback-core.md`) was not approved, and the 2026-11-12 rule that no pygame function is replaced stands. The three sites read `display_surface()`: the window for a game that owns it, the render target inside a tile. The two `assert screen is not None` there became a `RuntimeError` naming the problem (an assert is stripped under `-O`).
- **The class, and its invariant**: a member calls a pygame function that answers for the whole process, not for its engine context. `tests/test_workspace_config.py::test_no_game_demo_or_app_reads_the_window_instead_of_its_own_screen` scans every game, demo and app for `pygame.display.get_surface` however it is spelled (attribute chain, from-import, module alias; checked by `test_the_screen_guard_finds_every_spelling`). It failed on the old Bitmappy, naming the three sites.
- **Sweep** (every game, demo and app, for process-wide pygame calls): `pygame.display.get_surface` only in Bitmappy, now fixed. Still open: Bitmappy's `pygame.mouse.set_visible` (`animated_canvas.py`, its canvas hover) and the text-input demo's `pygame.key.set_repeat(350)`, with the engine's own `InputBox` repeat. Both are planned as engine events applied only by the context that owns the window (plans/future-work.md, the cursor show/hide event and the key-repeat event, the owner, 2026-11-20); the guard widens to them then. Bitmappy's `main()` also sets the process's multiprocessing start method (`editor.py:1643`), which is not pygame and not covered here (Arcade sub-plan 5's plan).
- **Tests**:
  - `src/apps/bitmappy/tests/test_bitmappy_editor_scene.py`: inside an inner context with a 700-wide target, the film strip runs to the target (`700 - 341`), not the 800-wide display. It failed on the old code (459); with no screen, the error is raised.
  - `src/apps/bitmappy/tests/test_bitmappy_animated_canvas_sprite.py`: inside a short 800x200 target, the canvas's pixels are smaller than on the 800x600 display. It failed on the old code (40 and 40); with no screen, the error is raised.
  - `tests/test_every_recording_replays_inside_an_inner_game.py`: Bitmappy's strict xfail is removed (`DIVERGES_INSIDE_A_TILE` is empty), and its tile pair passes (41 passed; the one xfail left is the text-input demo's key repeat).
