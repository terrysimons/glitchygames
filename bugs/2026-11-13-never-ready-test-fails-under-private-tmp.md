# The Never-Ready Reproducer Test Fails in Every Checkout Under /private/tmp

- **Description**: `tests/test_reproduce_orphaned_test_processes.py::test_a_run_that_never_reaches_the_moment_leaves_nothing_running` (from #192, BUGS.md #275) failed every time in a checkout under `/private/tmp` (a worktree in Claude's scratch directory, `/private/tmp/claude-501/...`), on plain main as well as on branches, and passes in the main checkout. Under the shuffled pre-push suite it was the one failure (`1 failed, 26350 passed`), so pushes had to be made from the main checkout.
- **Status**: Fixed (2026-11-20, branch `fix/bug-sweep-2026-11-20`)
- **Priority**: Low (only checkouts under the temporary directory; blocks a push from one)
- **What the evidence shows**: the test patches `MOMENT_TIMEOUT_SECONDS` to 5.0 (line 131) and expects its inner pytest run to reach a test body that writes `stand-in-child.pid`; under `/private/tmp` the inner run never got there within the 5 seconds, so reading the file raised `FileNotFoundError` (the main checkout takes about 5.5 s for the whole test). Outside pytest the same never-ready trial, run through `scripts.reproduce_orphaned_test_processes` with the same 5-second patch, reached its test body in about 1.0-1.3 s in both places (`reached=True after 1.0 s` under `/private/tmp`, `0.9 s` in the main checkout). So the slowdown, or a block, appears only when the trial runs inside the outer pytest run in that location.
- **Root cause (confirmed 2026-11-20)**: with no config file, pytest takes the common ancestor of the working directory and the test as the rootdir, unless that ancestor is the filesystem root. The checkout under `/private/tmp/...` and the outer test's `tmp_path` under `/private/var/folders/...` share `/private`, so the inner run printed `rootdir: /private` (its `run.log`) and its two xdist workers had not collected after 5 s (`KeyboardInterrupt`, `no tests ran in 5.27s`). In `/Users/...` the common ancestor is `/`, so pytest fell back to the test's own folder (`rootdir: .../test_a_run_that_never_reaches_0`, `2 workers [1 item]`). By hand, with the checkout in `/private/tmp` and the test file at its resolved `/private/var/...` path: `rootdir: /private` took 2.5-3.1 s (`-n 2` and `-n 0`), `--rootdir=<the test's folder>` 0.44 s. Why a `/private` rootdir is slow was not found. It explains why the standalone script (an unresolved `/var/...` path, common ancestor `/`) was fast.
- **Solution**: `scripts/reproduce_orphaned_test_processes.py` `rootdir_options` passes `--rootdir=<the test file's folder>` for a test given by an absolute path; a test named relative to the checkout (the default) keeps its config. The test passed 3 of 3 in a checkout under `/private/tmp` after the fix, and failed there every time before.
- **Tests**: `tests/test_reproduce_orphaned_test_processes.py` `test_a_test_outside_the_checkout_pins_the_runs_rootdir` (failed before the fix) and `test_a_test_node_of_the_checkout_keeps_the_checkouts_rootdir`; the original test itself now passes under `/private/tmp`.
- **Was suspected, unverified (ruled out)**: something in the outer run that matches temporary-directory paths, such as the harness's process sweep (`tests/child_process_guard.py`) or a `tmp_path` rule, stops or delays the inner run there. Next checks: run the test with `-p no:xdist` and with the child-process guard disabled in a `/private/tmp` checkout; keep the inner run's temporary directory (patch the reproducer's `tempfile.TemporaryDirectory` to `delete=False`) and read its `run.log` to see how far it got.
- **Test gap**: the test's 5-second wait assumes the inner run starts as fast everywhere as in the main checkout; nothing reports how far the inner run got when it times out.
