# A Docs Deploy Published a Stale Games Site, and Zombies Ain't My Neighbors Left play/

- **Description**: The published docs lost Zombies Ain't My Neighbors' browser game (`play/zombies-aint-my-neighbors`), though its docs pages stayed. CircleCI's deploy of main at 4e5cc83d (gh-pages 10c3df72, 2026-11-20 04:34 UTC) had it; two deploys of the same commit by hand from the owner's machine (e5f0dde1 at 21:28 and 3a80c287 at 21:33, 2026-11-19 Pacific) published a play/ without it, e5f0dde1 deleting its 31 files. The main checkout's `build/browser/site` was built 2026-11-13, six days before #215 made Zombies a browser game, and has no folder for it.
- **Status**: Fixed (2026-11-19, on `fix/docs-play-stale-browser-site`)
- **Priority**: High (the public site's playable games; any game changed since the last local build would publish its old version the same way)
- **Root Cause**: `scripts/mkdocs_hooks.py` `on_post_build` copied whatever `build/browser/site` held into the site as play/, unchecked. `nox -s docs-deploy` rebuilt that site before `mkdocs gh-deploy`, but a deploy run another way (a bare `mkdocs gh-deploy`) skipped the rebuild and published the checkout's old games site. A deploy without any games site would have published no play/ at all.
- **Test gap**: the hook's tests checked that a games site is copied and that a missing one leaves play/ out, never which commit the copied site was built from; nothing tied the published games to the code being deployed.
- **Solution**: a deploy (`gh-deploy`, however it is run) builds the browser games afresh itself (`build_browser_games`: `python -m scripts.build_browser_bundle all`), as a game may have changed (the owner, 2026-11-19), and `nox -s docs-deploy` no longer builds them first. `build_browser_bundle all` stamps the site (`site_build.json`: the commit it was built from and its games); the hook publishes play/ only when the stamp names HEAD and every game it lists has its page, and otherwise stops the deploy before anything is pushed, naming why and the command that builds the games. A local build (`docs-serve`, `lint-docs`) builds no games (that needs the pygame-ce wheel's WebAssembly toolchain): it copies a games site built from HEAD and otherwise leaves play/ out with an info line (not a warning, which would stop the strict build).
- **Verified**: the hook's deploy path run for real on the branch rebuilt all seven games, stamped with the branch's HEAD, and copied them in, Zombies Ain't My Neighbors included; pointed at the main checkout's 2026-11-13 site, it refused ("has no site_build.json ... Build the games with uv run python -m scripts.build_browser_bundle all") and wrote no play/.
- **Tests**: `tests/test_mkdocs_hooks_browser_games.py`: a deploy refuses a games site that is missing, unstamped, another commit's or short a game it lists, and a local build leaves each out; gh-deploy builds the games afresh before publishing them, and a local build never builds; a failed build stops the deploy; the builder runs from the repository root; the hook's and the builder's stamp names are held equal. `tests/test_build_browser_bundle.py`: `all` stamps the site with HEAD and every game; a commit git cannot name stops the build. `tests/test_ci_config.py`: `docs-deploy` leaves the games to gh-deploy, and `--build-only` builds them before the docs.
- **Siblings** (other places the docs build or a build tool reuses something built earlier, 2026-11-19): covered. The complexity graphs are regenerated when made from another commit (`generate_complexity_graphs.generate_if_stale`); the performance graphs are generated on every build; the pygame-ce wheel is reused only when `dist-pyodide/build-info.json` names the submodule's current commit with no uncommitted changes (`build_browser_bundle.reusable_wheel`).
