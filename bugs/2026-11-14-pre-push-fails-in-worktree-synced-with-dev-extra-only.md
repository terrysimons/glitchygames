# Pre-Push Checks Fail in a Worktree Synced With Only the dev Extra

- **Description**: In a new worktree synced with `uv sync --locked --extra dev`, the pre-push `static-analysis` and `test-random` hooks fail on missing modules (`ModuleNotFoundError: No module named 'mkdocs'`, `mkdocs_gen_files`, `cookiecutter`), in tests such as `tests/test_gen_ref_pages.py` and `tests/templates/test_template_errors.py`. `uv sync --locked --all-extras --all-packages` fixes it. Seen 2026-11-06 on the `fix/numpy-2` worktree, where the failure came at the end of a 20-minute push (the `feat/default-wayland` worktree was synced the same way)
- **Status**: Fixed (2026-11-22, `fix/hooks-install-everything`): `test-random` was fixed 2026-11-19 (`9a2127ec`); `static-analysis` was not, though the record was closed 2026-11-20, and it failed again 2026-11-22 in two new worktrees
- **Priority**: Low (a re-sync fixes it, but only after a long push fails)
- **Reporter**: Claude, pushing from new worktrees
- **Date Reported**: 2026-11-14
- **Details**: Either the hooks should run in an environment that has every extra they need (as `docs-serve` does since #274: `uv run --isolated ... --all-extras`), or a check before the slow hooks should say which sync is missing
- **Files**: `.pre-commit-config.yaml`, `noxfile.py`, `.envrc`, `API_README.md`, `tests/test_ci_config.py`
- **The 2026-11-20 closure**: it checked that `test-random` runs isolated with every extra (`noxfile.py` 876-884, since `9a2127ec`) and that `static-analysis` installs its own nox environment from the lock file with every extra (`_install_from_lockfile`), and concluded neither depends on `.venv`. It did not rebuild a dev-extra-only `.venv` and push through the hooks, and that was the step that would have shown `static-analysis` still failing.
- **Root cause** (2026-11-22): basedpyright resolves imports against the repository's `.venv`, not the environment nox runs it in. Run from the nox session's environment, with that environment first on `PATH` and `VIRTUAL_ENV` set to it, `basedpyright --verbose` prints `Execution environment: <worktree>/.venv/bin/python` and searches `<worktree>/.venv/lib/python3.15/site-packages` (basedpyright 1.40.2 picks a project-root `.venv` by itself; `pyrightconfig.json` names no environment). The commit hook (`uv run --locked --extra dev nox -s measure-staged`) is the first thing to build a new worktree's `.venv`, with only the dev extra, so the push's `static-analysis` failed on 17 imports (`scripts/mkdocs_hooks.py` 57 and 66, `src/glitchygames/templates/game.py` 16, `tests/templates/test_template_errors.py` 12, `tests/test_gen_ref_pages.py` 12, ...) although nox had installed them. ty follows `VIRTUAL_ENV` to nox's environment and passed. Reproduced in a detached worktree of `main` (6163d80c): 17 errors before, 0 after.
- **Fix** (the owner's choice, 2026-11-22: "just have the dev hook install everything"): every hook runs `uv run --all-extras --all-groups --all-packages` (the two measuring hooks keep `--locked`), so whichever runs first fills a new worktree's `.venv` with everything `uv.lock` pins. `uv run` only adds, so a full `.venv` is untouched. `API_README.md`'s development setup is now the full sync too. basedpyright still reads `.venv`, not nox's environment: considered and not chosen were pointing it at the session's Python (`--pythonpath`) and naming one environment in every tool's config.
- **Test gap and invariant**: nothing checked what the hooks install. `tests/test_ci_config.py::test_every_hook_installs_every_extra_group_and_package` fails on any hook that runs `uv run` without `--all-extras`, `--all-groups` and `--all-packages`, or with `--extra` (shown failing with `lint` planted back on `--extra dev`).
- **Sweep** (other gate tools that might read `.venv` by themselves): ty follows `VIRTUAL_ENV` (checked). Not checked one by one: the other sessions' tools (ruff, deptry, bandit, pytest, mkdocs), which run as the nox environment's own executables. `scripts/measure_on_raspberry_pi.py` still runs `uv run --locked --extra dev nox -s measure-staged` on the Pis, whose clones need no docs extras.
