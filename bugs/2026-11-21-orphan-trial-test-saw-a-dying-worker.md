# The Orphan-Trial Test Saw a Dying Worker as Left Running

- **Description**: in the pre-push gate's shuffled run (`nox -s test-random`, Python 3.15, seed 2725850629, 2026-11-21, pushing `fix/browser-pacer-judder`), `tests/test_reproduce_orphaned_test_processes.py::TestTrials::test_the_command_reports_each_trial_and_exits_on_what_it_found` passed, then errored at teardown: "the test left 1 process(es) running (now killed): pid 22647: (python3.15)". The other 30,618 tests passed. Run alone, it passed 3 times of 3. Other sessions were running suites on the same Mac at the time.
- **Status**: Open (recorded only: the owner's freeze on new work, 2026-11-21)
- **Priority**: Low (a flake under load; it fails a push's gate, and a second run passes)
- **What the evidence shows**: the leftover's command line was `(python3.15)`. macOS `ps` shows a process in parentheses when it can no longer read its arguments: one exiting or a zombie (a killed child not yet waited for shows `<defunct>`). So the guard (`tests/child_process_guard.py` `stop_leftovers`) listed a process that had already been signaled, not one still running.
- **Likely cause (unverified)**: `scripts/reproduce_orphaned_test_processes.py` `end_the_run` ends the inner pytest run with `stop_command`, which waits only for the group's leader, then sends SIGKILL to the run's whole group (`os.killpg(run.pid, SIGKILL)`) and waits for nothing else. The run's xdist workers are in that group, but they are not the outer test's children: once the leader is gone they are reparented to launchd, which reaps them when it gets to them. The guard then finds every process in a group a recorded child led (`leftover_processes`), and `ps` lists each one until it is reaped. On a busy machine a worker killed a moment earlier is still in that listing. The guard leaves out a zombie only when it is the test's own child (`poll()` reaps it), never a zombie or exiting member of a led group.
- **To confirm**: add the `stat` column to `PROCESS_LISTING_COMMAND` and log the leftover's state, then repeat the trial test under load, for example `pytest -n auto` with a CPU hog beside it.
- **Possible fixes** (choose after confirming): the guard leaves out processes whose state is `Z` (zombie) or `E` (exiting), the same rule it already applies to its own children; or `end_the_run` waits until the run's group is empty (polling `ps` for the group, with a timeout) before the sweep, so the trial ends with nothing left in its group.
- **Test gap**: the guard's tests list processes as fixed rows with no state column, and nothing runs a trial while the machine is loaded.
- **Siblings**: any test whose child process group outlives its leader and is ended with `killpg` and no wait for its members. Not swept yet.
